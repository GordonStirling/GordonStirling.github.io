Adding Value as a Data Practitioner / 04

DELIBERATE VALUE CREATION

This is part 4 of the Adding Value series, exploring how data practitioners create value in the real world.

Once we have discovered the purpose, how do we deliberately create value?

Retreat behind the laptop, analyse the data and spend days crafting the perfect solution before putting it in front of the people it was designed to support.

Finding the right problem is only the start. We can spend days building something that makes sense to us but has no utility for the people who it is designed for.

Value is designed, not delivered.

Creating value is not simply about identifying a need and then disappearing until we have a finished solution. It is about building fast, sharing, learning and iterating as our understanding of both the problem and potential solutions develop. Value is designed with the human in the loop.

The Value Creation Loop provides a simple way of thinking about this process.

Purpose

Purpose gives us a way to navigate complexity, provides an initial direction and enables us to make deliberate choices based on what matters.

Who are we trying to support?

What problem are we trying to solve?

What are we trying to change or influence?

This becomes our design brief for everything that follows.

Build

Once the purpose is clear, we need to build something. Not the end product with all the bells and whistles, the goal of this stage is to build something that has the potential to create influence. To do this, we need to get three things right.

Get the Right Data to the Right People at the Right Time.

The data needs to provide enough context to improve understanding. It needs to reach the people whose judgements, decisions or actions we are trying to support, and it needs to arrive while there is still an opportunity to influence what happens next. Two out of three is no good, we need all three to create influence and add value. Otherwise, we are just producing noise.

Iteration

In Build, iPod and iPhone co-creator Tony Fadell presents the concept of Heartbeats. A heartbeat is a set of deadlines that create a rhythm or cadence for a design team. The heartbeat forces regular iterations, creating opportunities to learn and develop while keeping the people involved in the work connected. This is the goal of the iteration stage; refine the build by involving the people it is designed to support. Not every heartbeat needs to involve everyone, but the end users should be involved often enough to help shape the design.

What do they engage with?

What do they ignore?

What is confusing?

What questions do they ask?

How will they use it?

Feedback should be central to the design process.

Launch

As practitioners, we need to avoid getting stuck in iteration, paralysed by the search for perfection. We can’t create influence if the work remains in development. Launch is where we put the potential solution into practice.

This is not the end of iteration, it is where the solution begins to interact with the real world. Putting the solution into practice gives us a different type of feedback and exposes the assumptions we have made throughout the process. Do people actually use it? Does it improve understanding? Does it influence judgements, decisions or actions? Meadows (2008) argued that purposes are deduced from behaviours rather than stated goals. Similarly, we only really understand the value of a solution by seeing how people engage with it in practice.

Integrate

Only once a workflow has demonstrated that it can add value by creating influence should we consider integrating it into routine practice. If it is not adding value, we need to assess why and either return to an earlier stage of the loop to refine the solution or remove the workflow completely.

Integration should be earned through demonstrated value.

The goal of the integrate stage is to maximise the value added by the workflow while minimising the time and effort required to sustain it.

Maximising the value is about increasing the influence the workflow creates over time. How do we do this? Relevant outputs encourage use. Use increases utility. Utility builds trust. Trust brings analysis into conversations earlier. Earlier involvement creates greater context which enables increasingly relevant outputs. Each successful turn strengthens the next. The flywheel turns, momentum builds and the workflow becomes embedded in routine practice, repeatedly and reliably informing judgements, decisions and actions (Collins, 2019).

We also want to make the workflow more efficient. What can be standardised? What can be automated? Where does human judgement still add value?

The goal is not to automate everything, it is to remove unnecessary effort without removing the context, interpretations and judgements that make the workflow valuable.

The Value Creation Loop gives us a structure for deliberately creating value, one workflow at a time. As more valuable workflows become integrated into practice, the challenge begins to shift. We are no longer just building useful workflows, we are building a sustainable, resilient and adaptable analytical system that can continue to create value over time.

This is the starting point for Building Resilient Systems.
